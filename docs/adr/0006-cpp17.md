# 0006. C++17

- **Status:** Proposed
- **Date:** 2026-11-11

## Context

The project is written in C++ and must build on Ubuntu (x86) for development and CI, and on Raspberry Pi OS (ARM) in the car. The language standard decides which features and libraries are available, and which compilers and toolchains can build the code.

## Decision

The project uses C++17, set in CMake with `CMAKE_CXX_STANDARD 17` and `CMAKE_CXX_STANDARD_REQUIRED ON`, without compiler-specific extensions.

## Alternatives considered

- **C++20.** Adds concepts, `std::span`, ranges and designated initialisers, and the GCC on Ubuntu 24.04 supports most of it. Not chosen because C++17 is still the most common standard in embedded and automotive toolchains, and the project should reflect that.
- **C++14 or older.** Loses `std::optional`, `std::variant`, `std::string_view`, `if constexpr` and structured bindings, which make the code clearer and safer.

## Consequences

- Available: `std::optional`, `std::variant`, `std::string_view`, `std::array`, `if constexpr`, structured bindings, `[[nodiscard]]`.
- Not available: `std::span` (use a pointer and a size, or a small span type of our own), concepts, ranges.
- The decision can be revisited with a new ADR if a C++20 feature becomes important.
